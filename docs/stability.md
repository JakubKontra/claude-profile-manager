# Stability

From 1.0, cpm follows [Semantic Versioning](https://semver.org). Within 1.x, the interfaces below change only in compatible ways: new commands, flags, config keys and JSON fields may appear, and nothing listed here is removed, renamed or given a new meaning. A change that breaks them waits for 2.0.

## What is covered

### Config files
- **`config.toml`:** every documented key and its meaning. The `version` key sets the format. A missing `version` means 1. A cpm that reads an older format migrates it in memory and leaves the file alone. A config with a newer `version` than cpm supports is refused, and the error says to upgrade.
- **`secrets.toml`:** `[profiles.<name>.env]`. It must be a regular file with mode `0600`.
- **Unknown keys** are reported by `cpm doctor` as a warning, never as an error.

### Commands and flags
- Every command, its arguments and its flags, as listed in [`cmd/testdata/cli-surface.txt`](../cmd/testdata/cli-surface.txt). A test fails when that list changes.
- `--dry-run` exists on every command that deletes or overwrites data: `install`, `remove`, `rename`, `cloud push`, `cloud pull`.
- Irreversible deletion (`remove --purge`) asks for confirmation. `--yes` skips the question. Without a terminal and without `--yes`, the command refuses. `rename` does not ask, because it reverts itself on failure.

### JSON output
- `--json` writes exactly one JSON document to stdout, and only on success. Errors go to stderr, and the exit code says what happened.
- Progress messages, and the output of programs cpm runs (such as `claude auth login`), go to stderr in JSON mode.
- Fields are only ever added. An existing field keeps its name and type. Optional fields may be omitted when empty, as the goldens show.
- The shapes are pinned in [`internal/testdata/json/`](../internal/testdata/json/).
- `detail` texts (in `doctor`, `login`, `rename`) are free-form text for humans. Do not parse them.

### Exit codes

| Code | Meaning |
|------|---------|
| `0` | Success |
| `1` | Error |
| `2` | Wrong usage: unknown command or flag, wrong arguments |
| `3` | A check failed: `cpm doctor`, local edits blocking `install --sync`, or a cloud sync conflict |
| `4` | `cpm login` could not log in a profile |

### Shell and wrapper contract
- **Wrappers:** `claude-<name>` in `bin_dir` begins with the line `# Generated by cpm (Claude Profile Manager)`. cpm replaces only files that carry this line.
- **Environment:** `cpm use` and the hook set `CLAUDE_CONFIG_DIR`, `CLAUDE_PROFILE` and `CPM_MANAGED_VARS` (the list of variables cpm set, so it can unset exactly those).
- **`cpm resolve [dir]`** is hidden but frozen, because generated hook scripts call it. It prints the profile for `dir` (default: the current directory) or nothing, and exits 0.
- **`.claude-profile`** holds one profile name.

### Files on disk
- **`~/.claude-profiles/`** (the directory of `config.toml`) contains `config.toml`, `secrets.toml`, one directory per profile, `cloud/` and `.cpm/` (cloud state and backups).
- **Each profile directory** contains `.cpm/profile` (the name) and `.cpm/baseline/` (the copied source files).

### Cloud repository
The layout of the sync repository is shared between machines that may run different cpm versions:
- `cpm/config.toml`,
- the synced files from `source_dir` (`settings.json`, `CLAUDE.md`, `commands/`, `skills/`, `agents/`, `plugins/` and so on),
- any files added later.

A file outside the synced directories that a cpm version does not know about is left alone by that version, so a newer cpm can add files to the repository.

## What is not covered

- **Human-readable output**, its wording and its layout. Use `--json` in scripts.
- **The Keychain service names.** They follow Claude Code (`Claude Code-credentials-<sha256(CLAUDE_CONFIG_DIR)[:8]>`), and cpm changes along with Claude Code.
- **The Go packages** under `internal/`. They are not an API.
- **Behavior outside macOS and Linux.** Windows is supported only through WSL.
